# The rules cicd's ScanTaint runs with Opengrep's interfile analysis.
#
# Every rule in https://github.com/semgrep/semgrep-rules at commit
# 16b9e6d45f10649f6a531ec4838ed9924372c3bc that sets `options.interfile: true`
# and that p/security-audit or p/owasp-top-ten (the pinned manifests beside
# this file) already carries. That flag is the rule author's statement that the
# rule means more across functions and files; it is the selection, not a
# judgement cicd made rule by rule. Rows are generated: load each staged rule
# file, keep the rules whose options.interfile is true, and spell the id the
# way the other manifests do. Same format:
#
#   <path in semgrep-rules> <rule id as semgrep reports it>
#
# 23 are taint-mode rules and 4 are search-mode (the hardcoded-secret express
# and jose rules, and the directory-listing check). No C# rule at this commit
# sets the flag, so a .NET tree gets nothing from ScanTaint.
#
# Every rule here must be loaded, or the scan is a non-run, as for the other
# manifests. Bumping the semgrep-rules commit regenerates this file; see
# specs/report-cross-file-taint-as-advice.md.
